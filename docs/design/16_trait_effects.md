# 16. 특성 효과 시스템

## 1. 원칙

- **특성은 변수만 바꾼다.** 행동과 결과는 공통 시스템(경제 14번, 상호작용 03번, 비밀 05번, 범죄 09번, 승계 15번 S1~S7)이 낸다.
- 특성이 바꿀 수 있는 변수, 행위, 조건, 지표, 행동은 모두 `data/registry.json`에 있다. 거기에 없는 것을 쓰면 검증기(`tools/validate/validate_traits.py`)가 오류를 낸다.
- 특성 데이터는 `data/traits/*.json`이다. Godot이 그대로 읽는다. 이 문서는 형식과 계산 규칙을 정한다.

## 2. 효과 종류 8가지

| type | 필드 | 런타임 동작 |
|---|---|---|
| `mod` | var, op(add/mul/set), value, who, if, arg | 변수 하나를 바꾼다. 적용 순서: add 합산 → mul 곱 → set. set이 둘 이상이면 법 > 교리 > 부족법, 시법, 헌장 > 가훈 > 규율 등 > 관습 순으로 이긴다. 같은 단계면 나중에 채택한 쪽 |
| `norm` | behavior, status(forbidden/allowed/required), severity(0~100), who, exempt | 집단 규범. 3절 |
| `justify` | behavior(또는 `*`), holder, value(0~1), who, if | 특정 인물(holder)이 규범을 어겨도 관찰자(who)가 덜 반응하게 한다. 3절 |
| `opinion` | from, to, value, if | 상시 호감 보정. 호감 = 사건으로 쌓인 기억 호감(감쇠함) + Σ 상시 보정 |
| `enable` / `disable` | action, who | 행동을 메뉴와 AI 후보에 넣거나 뺀다 |
| `ai` | action, weight, who, if | 그 행동의 효용에 곱한다(15번 S3와 같은 효용 계산) |
| `event` | event, chance_per_year, who | 해마다 확률로 사건 발생 |
| `slot` | slot(trait/succession), value | 집단 슬롯 가산 |

**who / from / to / holder**는 레지스트리의 scopes 중 하나다. **if**는 predicates 목록이고 모두 참일 때만 적용한다. 인자가 있는 조건은 `has_history:살인자`처럼 쓴다.

**arg**: 인자를 받는 변수(기술 지정, 행동 지정, 생업 지정 등)는 `"arg": "언변"`처럼 준다.

## 3. 규범, 반응, 정당화

### 3-1. 규범

집단은 행위(behaviors)마다 상태를 정한다.

| 상태 | 뜻 | 05, 09번과의 연결 |
|---|---|---|
| forbidden | 금지 | 위반은 그 집단의 범죄(09번 1절). 위반 비밀의 무게 × 1.5 |
| allowed | 허용 | 비밀이 되지 않거나 무게 × 0.3 |
| required | 의무 | 그 행위를 해야 한다(예: 도제 두기, 피의 맹세의 살인). 하지 않으면 위반 |

**행위 이름 규칙**: 실패를 이름으로 삼은 행위(헌물 미납, 다산 의무 미달, 출가 거부, 결투 거부)는 forbidden으로 쓴다. "미납을 금지한다"가 곧 "납부 의무"다. required는 긍정형 행위에만 쓴다.

규범이 없는 행위는 사회적 수치만 남는다. 수치의 기본 심각도는 05번 비밀 기본 무게를 쓴다.

**exempt**: `[면제: 수장]` 같은 적용 범위(04번 3-1절). 면제된 사람에게는 그 행위가 위반이 아니다. 대신 3-4의 불공정 비용이 생긴다.

### 3-2. 반응 공식

관찰자 o가 인물 x의 행위 B를 알게 되면(목격, 소문, 폭로) 한 번 반응한다.

```
반응량 = 심각도(B) × 내면화(o) × (1 - 정당화(x, B, o)) × 증거 배수

심각도(B)   = o가 따르는 모든 규범 중 B의 최대 severity
             (규범이 없으면 05번 기본 무게, 허용이면 0)
내면화(o)   = 0.6 + Σ 성격 가산      (0 ~ 1.4로 제한)
             성격 가산: 독실 +0.4, 정직 +0.2, 냉소 -0.4, 기만 -0.2, 색욕 -0.2(성 관련 행위만)
정당화      = 1 - Π(1 - j_k)          (x에게 적용되는 justify 효과 j_k를 모두 합성)
증거 배수   = 소문 0.5, 증언 0.8, 문서·목격 1.0 (05번 5절)
```

**반응량의 효과**

| 효과 | 크기 |
|---|---|
| 호감(o→x) | -반응량 |
| x가 o가 속한 집단의 수장이면 충성(o→집단) | -반응량 × 0.5 |
| 반응량 20 이상이고 o가 정직 성격이면 폭로 효용 | +반응량 (05번 4절 선택에 가산) |
| 반응량 40 이상이면 원한(o→x) | +반응량 × 0.5 |

### 3-3. 정당화

정당화는 "이 사람은 해도 된다"는 믿음이다. justify 효과로만 생긴다.

| 출처 | 대상 행위 | holder | j |
|---|---|---|---|
| 기적 숭배 교리 | 전체 | 교주 | 0.5 |
| 신성한 혈통 교리 | 전체 | 교주 가문 | 0.5 |
| 성혼 교리 | 다수 배우자, 첩, 혼외 관계, 신도끼리의 관계 | 교주(범위에 든 사제 포함) | 0.7 |
| 교주 무오류 교리 | 전체 | 교주 | 0.8 |
| 왕권신수 법 | 전체 | 나라 수장 | 0.5 |
| 영웅 숭배 부족법 | 살인, 폭행, 약탈 | 전쟁 영웅 이력 보유자 | 0.4 |

독실 성격 관찰자는 정당화 j에 × 1.25(최대 0.95). 냉소 성격은 × 0.5.

### 3-4. 공개 특권의 불공정 비용

`[면제: 수장]`처럼 공개로 특권을 걸면, 면제받지 못한 구성원은 매년 충성을 잃는다(04번 3-1절의 수치).

```
연 충성 감소 = 기본 감소(범위별 3, 4~8, 10) × 내면화(o) × (1 - 정당화(수장, *, o))
```

04번 3-1절의 "왕권신수, 기적 숭배, 신성한 혈통 중 하나면 절반, 둘이면 4분의 1"은 이 공식에서 j = 0.5를 합성한 결과다(1 - 0.5 = 0.5, 1 - 0.5 × 0.5 = 0.75).

### 3-5. 계산 예: 일부일처 교단, 교주가 아내 4명

일부일처 교리: 다수 배우자 forbidden, severity 30. 관찰자는 독실 성격 신도(내면화 1.0, 정당화 × 1.25), 증거는 목격(1.0).

| 교단 상태 | 정당화 | 반응량 | 신도 1명의 충성 | 결과 |
|---|---|---|---|---|
| 위선(몰래), 정당화 없음 | 0 | 30 | -15 | 들킬 때마다 신도 호감 -30. 정직한 신도는 폭로 효용 +30 |
| + 기적 숭배 | 0.5 × 1.25 = 0.625 | 11.3 | -5.6 | |
| + 성혼 | 0.7 × 1.25 = 0.875 | 3.8 | -1.9 | 거의 신경 안 씀 |
| + 성혼 + 교주 무오류 | 1 - (1 - 0.875)(1 - 0.95) = 0.994 | 0.2 | 0 | 전혀 신경 안 씀 |
| 냉소 신도(내면화 0.2), 성혼 | 0.35 | 3.9 | -2.0 | 원래 안 믿어서 덜 반응 |
| 독실 신도, 성혼 있고 남편이 피해자 | 0.875 | 3.8 + 배우자 원한(05번 불륜 +40)은 별도 | | 정당화는 규범 반응만 줄인다. 아내를 뺏긴 개인 원한은 남는다 |

마지막 줄이 중요하다. 정당화는 **규범 위반 반응**만 줄인다. 피해 당사자의 개인 원한(배우자, 피해자 가문)은 05, 09번 규칙대로 따로 쌓인다.

## 4. 성격의 특성 반응

집단 특성마다 likes(좋아하는 성격)와 dislikes(싫어하는 성격)를 둔다(04번 3절).

| 시점 | 좋아함 | 싫어함 |
|---|---|---|
| 채택 직후 1회 | 충성 +10 | 충성 -15 |
| 유지 중 매년 | 충성 +1 (누적 최대 +10) | 충성 -2 (누적 최대 -20) |
| 폐지 직후 1회 | 충성 -10 | 충성 +10 |

## 5. 수치 척도

새 효과를 정할 때 이 척도를 쓴다.

| 크기 | 호감, 충성, 위신 가산 | 판정 가산 | 배수 | 규범 심각도 |
|---|---|---|---|---|
| 작음 | 5 | 5 | 0.9 / 1.1 | 10 |
| 보통 | 10~15 | 10 | 0.75 / 1.25~1.3 | 20~30 |
| 큼 | 20~30 | 15~20 | 0.5 / 1.5 | 40~60 |
| 매우 큼 | 40 이상 | 25 이상 | 0.3 이하 / 2 이상 | 70~100 |

규범 심각도는 05번 비밀 기본 무게와 맞춘다: 혼외 관계 30, 사생아 40, 근친 40, 배교 35, 살인 50, 위조 60, 반역 70, 혈통 위조 80.

## 6. 해금 조건

```json
"unlock": [
  {"metric": "group.followers", "op": ">=", "value": 300},
  {"metric": "group.has_trait", "arg": "doctrine.miracle_worship", "op": "==", "value": 1, "keep": true}
]
```

- 모든 조건이 참이면 목록에 나타난다.
- `keep: true`인 조건은 08번의 (유지): 조건을 잃은 뒤 1년 안에 되찾지 못하면 특성이 폐지된다.
- metric은 레지스트리 metrics 목록에서 고른다.

## 7. 데이터 형식

파일 하나는 이 구조다.

```json
{
  "proposed": {"vars": {}, "behaviors": {}, "actions": {}, "metrics": {}, "predicates": {}, "events": {}, "scopes": {}},
  "traits": [ { ... }, { ... } ]
}
```

특성 하나:

| 필드 | 필수 | 내용 |
|---|---|---|
| id | 예 | `접두사.영문_소문자`. 전체에서 유일. 접두사는 아래 표 |
| name | 예 | 한국어 이름(문서와 같게) |
| kind | 예 | 레지스트리 kinds의 키(성격, 교리, 법 등) |
| tier | 예 | 기본 / 해금 / 없음(성격, 형질 등) |
| unlock | 해금이면 | 6절 |
| exclusive | | 배타 특성 id 목록. 양쪽이 서로를 적어야 한다 |
| likes, dislikes | 집단 특성 | 성격 이름 목록 |
| effects | 예 | 2절의 효과 목록. 비어 있으면 안 된다 |
| note | | 설계 의도 한 줄 |

종류별 추가 필드:

| kind | 필드 |
|---|---|
| 성격 | `pair`: 반대 성격 이름 |
| 형질 | `genetics`: {"dominance": "우성"/"열성"/"X열성", "carrier_freq": 0~1} |
| 재능 | `skill`: 관련 기술(없으면 null), `genius_effects`: 천재 등급에서 추가되는 효과 목록 |
| 숙련 | `skill`, `threshold`: 50 또는 80 |
| 이력 | `visibility`: 공개/비밀/둘 다, `trigger`: 생기는 조건(한 줄) |

**id 접두사**

| 접두사 | kind | 접두사 | kind |
|---|---|---|---|
| pers | 성격 | band | 규율(도적단) |
| gene | 형질 | merc | 계약 원칙(용병단) |
| talent | 재능 | order | 서약(기사단) |
| hist | 이력 | revolt | 요구(봉기군) |
| mastery | 숙련 | trade | 상규(상단) |
| family | 가훈 | guild | 조합 규약 |
| tribe | 부족법 | doctrine | 교리 |
| custom | 관습(마을) | school | 학풍 |
| city | 시법 | crime | 불문율(범죄 조직) |
| law | 법 | cabal | 맹약(비밀결사) |
| league | 헌장 | cabal_goal | 결사 목적 |
| | | faction | 파벌 요구 |

**특성 수준의 추가 필드** (검증기는 통과시키고, 엔진이 읽는다)

| 필드 | 쓰는 곳 | 뜻 |
|---|---|---|
| uses_slot | 상속법, 맹주 세습/선출 등 | "succession"이면 특성 슬롯이 아닌 승계 슬롯에 들어간다(15번 4-2) |
| auto_from | 관습 | 주민 성격 분포 조건. {"personality", "share"} 또는 그 목록 |
| applies | 봉기군 요구 | "on_victory"면 승리 순간 상대 나라에 적용. 법 우선순위로, 가장 나중에 채택한 것으로 본다 |
| duration_years | 봉기군 요구 | 효과 지속 연수 |
| repeals | 봉기군 요구 | 승리 시 폐지되는 법 id 목록 |
| fixed | 결사 목적 | 창설 때 고르고 바꿀 수 없음 |
| demand | 파벌 요구 | 최후통첩 내용 한 줄 |

**해금 조건의 OR**: 해금 조건은 모두 참이어야 한다(AND). 하나만 참이어도 되는 조건은 `{"metric": "cond.any", "arg": [조건, 조건], "op": "==", "value": 1}`로 쓴다.

**인자 형식**: 기술 기준치를 받는 지표는 `"arg": "학문:50"`처럼 콜론으로 쓴다.

**proposed**: 레지스트리에 없는 키가 꼭 필요하면 여기에 정의한다. 검증기는 경고로 보여 주고, 리뷰 뒤 레지스트리로 옮긴다.

## 8. 검증

```bash
python3 tools/validate/validate_traits.py
```

검사 항목: id 중복, kind와 tier, 모든 키의 레지스트리 존재, op와 수치 범위, 배타 관계의 대칭, 성격 이름, 종류별 필수 필드, 빈 효과 목록.

**런타임에서 지켜야 할 것** (데이터만으로는 강제되지 않음)

- 해방노예 빚 +3, 은인 빚 +5 같은 `rel.debt` 가산은 이력이 생기는 순간 한 번만 준다.
- 통솔, 행정 천재의 슬롯 +1은 그 인물이 수장인 집단에만 적용한다.
- 고리대금 금지 아래 대여자 제한(관대, 독실만)은 경제 시뮬레이터 규칙이고 데이터에는 없다.
