# 19. 시뮬레이션 규모와 연산 설계

집단 17종, 특성 381개, 상호작용 79개, 비밀과 범죄, 경제, 승계를 모두 넣는다. 사람 수는 수십만이 된다. 이 문서는 그 규모를 어떻게 버티는지 정한다. 측정값은 이 컨테이너(Godot 4.4.1, CPU 렌더러 llvmpipe)에서 잰 것이다.

|---|---|---|---|---|
| 소 64×64 | 4,096 | 약 100 | 약 2만 | 약 20만 |

마을 하나는 가구 40, 사람 약 200으로 잡았다(14번 경제 시뮬레이터의 필지 수 기준). 죽은 사람은 한 세대 30년, 10세대로 잡았다. 모든 사람이 개인으로 남아야 혈통 점수를 셀 수 있다(12번 7절).

집단 수: 마을 약 1,600, 가문 약 2만, 나라, 교단, 도적단, 상단 등 수백.

## 3. 구조: 시뮬레이션 핵심과 화면을 나눈다

```
┌──────────── 시뮬레이션 핵심 (C++ GDExtension, 작업 스레드) ────────────┐
│ 인물 표(열 단위 배열), 관계 표, 비밀 표, 집단 표, 가구·토지·창고 표    │
│ 사건 예약 바퀴(time wheel), 결정적 난수(인물 id + 용도 해시)           │
│ 효과 계산기(16번), 판정(03, 18번), 경제(14번), 승계(15번)              │
└───────────────▲───────────────────────────────┬────────────────────────┘
                │ 명령(플레이어 지시)            │ 변경 알림(보이는 사람만)
┌───────────────┴───────────────────────────────▼────────────────────────┐
│ 화면 (GDScript, 메인 스레드): 보이는 사람의 3D 모델, UI, 입력           │
└────────────────────────────────────────────────────────────────────────┘
```

- **핵심은 C++ GDExtension**으로 쓴다. 표준 Godot 빌드에서 돌아가고(.NET 빌드가 필요 없다), 위 측정대로 대량 갱신이 15배 빠르다. 이 컨테이너에 g++, cmake가 있고 godot-cpp 저장소에 접근된다.
- **화면은 GDScript**로 남긴다. 화면에 올라오는 사람은 많아야 수백이다.
- 파이썬 시뮬레이터(tools/econ_sim)는 검증 기준으로 남긴다. C++ 핵심이 같은 입력에서 같은 지표를 내는지 시험으로 확인한다.
- 인물은 객체가 아니라 **열 단위 배열**(나이 배열, 체격 배열, 가구 id 배열 …)로 둔다. 같은 값을 한꺼번에 훑는 계산이 캐시에 맞는다.

## 4. 상세도 세 단계 (12번 7절을 구체화)

| 단계 | 범위 | 시간 단위 | 위치 | 하는 계산 | 대 맵 인원 |
|---|---|---|---|---|---|
| 상세 | 내 가구 구역 + 인접 8구역 | 시간대 | 타일 위 좌표 | 이동, 개별 상호작용, 구경꾼, 작업 | 약 600 |
| 보통 | 반경 5구역 + 플레이어 혈통(r > 0) 인물 | 주 | 구역 | 주 1회 상호작용 판정, 비밀 발설, 가구 경제 | 약 4,000 |
| 요약 | 그 밖 | 계절(12주) | 마을 | 출생, 사망, 혼인, 이주를 확률로. 가구 경제는 마을 단위 합계 | 약 30만 |

### 4-1. 단계마다 쓰는 규칙이 같아야 한다

요약 단계 확률(혼인률, 출산률, 사망률, 계층 이동률)은 상세 모델을 돌려서 얻은 표에서 가져온다. 14번 경제 시뮬레이터가 이미 그 표를 만든다(계층별 자녀 생존, 이동성). 그래서 요약 마을과 상세 마을의 장기 통계가 같다. 이 일치를 시험으로 확인한다: 같은 마을을 100년 동안 요약으로 돌린 결과와 상세로 돌린 결과의 인구, 지니, 계층 분포가 10% 안에 들어야 한다.

### 4-2. 단계 올리기, 내리기

| 전환 | 하는 일 | 비용 |
|---|---|---|
| 요약 → 보통 | 사람마다 강한 관계 8개를 정식 관계로 펼친다. 이웃 관계를 첫인상 공식(03)으로 만든다 | 마을 1개 약 1ms |
| 보통 → 상세 | 타일 좌표 배치(집, 일터), 하던 일 배정. 3D 모델은 화면 근처만 | 구역 1개 약 2ms + 모델 |
| 상세 → 보통 | 위치를 구역으로 접는다. 진행 중 행동은 남은 시간만큼 결과를 즉시 정산 | 즉시 |
| 보통 → 요약 | 관계를 사람마다 8개(가족, 배우자, 연인, 원수, 가장 강한 것)만 남긴다. 나머지는 기억 합 1개로 접는다 | 즉시 |

모든 무작위는 (인물 id, 용도, 날짜)의 해시로 뽑는다. 언제 단계를 바꿔도 같은 시드에서 같은 결과가 나온다.

## 5. 연산을 줄이는 기법

### 5-1. 매 틱 훑지 않는다: 사건 예약

사람마다 "다음에 생각할 시각"을 사건 예약 바퀴에 넣는다. 그 시각이 된 사람만 계산한다.

- 밭을 가는 사람은 작업이 끝나는 시각에만 깨어난다.
- 비밀 발설 확률(05번 4절, 주당 p)은 매주 주사위를 굴리지 않는다. 다음 발설 시각을 지수분포로 한 번 뽑는다: `대기 주 = -ln(U) / p`. p를 바꾸는 입력(원한, 충성, 두려움)이 바뀔 때만 다시 뽑는다.
- 임신, 사망, 질병도 같은 방식으로 뽑는다.

### 5-2. 계산할 때만 계산한다: 지연 평가

- 기억 호감(18번 3-1)은 반감기 지수 감쇠다. 매주 줄이지 않고 (값, 기록 시각)만 저장한다. 읽을 때 `값 × 0.5^(경과 / 반감기)`로 정확히 계산한다. 갱신 비용이 0이다.
- 집단 지표(구성원 수, 권력 지분, 평균 충성)는 가입, 탈퇴, 충성 변동 때 더하고 뺀다. 다시 합산하지 않는다.

### 5-3. 효과 계산 캐시: 소속 서명

인물의 효과(16번)는 대부분 소속 집단의 특성에서 온다. 같은 마을, 같은 나라, 같은 교단, 같은 가문 사람은 같은 효과를 받는다.

```
소속 서명 = 해시(가문, 마을, 나라, 교단, 그 밖 소속, 신분)
서명마다 "평탄화한 효과표"를 한 번 계산해 둔다: 변수 id → (더할 값, 곱할 값, 덮어쓸 값)
인물 효과 = 서명 효과표 + 그 사람 성격, 재능, 이력 효과(사람마다 몇 개)
```

- 대 맵에서 서명 종류는 가문 수 정도(약 2만)다. 서명마다 실제로 건드리는 변수는 30개 안팎이라 표 하나에 0.4KB, 전체 8MB다.
- 입법으로 특성이 바뀌면 그 집단이 들어간 서명만 다시 계산한다.
- 규범 심각도(16번 3-1)도 서명별로 행위 → 최대 심각도 표를 만들어 둔다. 반응 공식이 표 조회 한 번이 된다.

### 5-4. 가까운 사람 찾기: 공간 격자

옆 사람 비키기, 구경꾼(18번 5절), 엿듣기는 반경 안의 사람만 본다. 2m 격자 칸에 사람을 넣어 두고 주변 9칸만 본다. 지금 n²(322명 15.7ms)이 n(예상 1ms 미만)이 된다.

### 5-5. 관계 저장 상한

| 단계 | 사람당 관계 상한 | 크기 |
|---|---|---|
| 상세, 보통 | 150 | 관계 1개 16바이트(상대 id 4, 호감 기억 4, 신뢰, 원한, 두려움 각 1, 단계 비트, 기록 시각) |
| 요약 | 8 | |

대 맵: 요약 30만 × 8 × 16B = 38MB, 상세·보통 4,600 × 150 × 16B = 11MB. 상한을 넘으면 기억이 가장 약한 관계를 지운다(이름만 기억하는 사이로 돌아간다).

### 5-6. 죽은 사람 보관

죽은 사람은 계보에 필요한 것만 남긴다: id, 부모 id 2개, 출생, 사망, 성별, 외형 유전자(6 × 2비트), 형질 대립유전자, 가문, 공개 이력 비트. 약 40바이트. 대 맵 300년 300만 명 = 120MB다. 최근 3세대만 메모리에 두고 나머지는 세이브 파일에서 필요할 때 읽는다(가계도 화면, 사생아 의심 지표의 조상 비교).

혈통 점수 r은 태어날 때 `(r_부 + r_모) / 2`로 한 번 계산해 저장한다(07번). 다시 계산하지 않는다.

### 5-7. 집단

| 계산 | 주기 | 대 맵 비용 |
|---|---|---|
| 입법, 투표(04번 6절) | 안건이 생길 때 | 사건 단위 |
| 집단 AI(수장의 출병, 약탈, 입법 발의) | 상세·보통 범위 집단은 주, 그 밖은 계절 | 집단 수백 × 수십 µs |
| 충성 변동 | 사건 때(특성 교체, 범위 특권 연간 감소는 연 1회 일괄) | |
| 집단 간 관계, 전쟁 | 주 | 관계 수천 |

집단은 사람보다 훨씬 적다. 집단 기능의 어려움은 연산량보다 규칙의 수에 있다. 그 규칙은 이미 데이터(특성 381개, 레지스트리 변수 310개, 검증기 오류 0)로 있고, 핵심은 그 데이터를 읽는 범용 계산기 하나다(16번).

|---|---|---|

## 7. 시간 예산 (가장 빠른 32x 기준)

32x에서 1시간대 = 0.125초다. 핵심 스레드는 그 안에 한 시간대 분량을 끝내야 한다.

| 단계 | 일의 양 | C++ 예상 | 1시간대 몫 |
|---|---|---|---|
| 상세 600명 | 시간대마다 깨어난 사람의 결정, 이동 | 사람당 수 µs ~ 수십 µs | 약 5ms |
| 보통 4,000명 | 주(21시간대)마다 사람당 약 20µs | 주 80ms | 약 4ms |
| 요약 30만 명 | 계절(252시간대)마다 사람당 약 2µs | 계절 600ms → **실측 계절 13ms** | 약 2.4ms → **실측 0.05ms** |
| 집단 | 주, 계절 | | 1ms 미만 |
| 합계 | | | **약 12ms / 125ms (10%)** |

같은 일을 GDScript로 하면 15배인 약 180ms가 되어 32x를 버티지 못한다. 중 맵(8만 명)도 32x에서 한계에 걸린다. 그래서 핵심을 C++로 옮기는 일은 선택이 아니고 전제 조건이다.

이 예산은 아직 추정이다. 아래 8절 1단계에서 실측한다.

### 7-1. 1단계 실측 (native/, 2026-11)

요약 단계 인구를 C++로 짜서 화면 없이 돌렸다(`native/build/sim_bench`). 단일 스레드.

| 항목 | 추정 | 실측 |
|---|---|---|
| 대 맵 30만 명, 1년 | 2.4초(계절 600ms × 4) | **51ms** (가장 느린 해 68ms) |
| 사람 1명, 계절 1회 | 2µs | 약 0.04µs |
| 32x 실시간 대비 | 2% | **0.04%** |
| 300년 뒤 누적 인물 | 300만 명, 120MB | 357만 명, **161MB**(1명 47.5바이트) |

- 사람마다 매 계절 사망 판정, 기혼 여성 임신 판정, 혼인 시장 짝짓기를 하고, 출산은 36주 뒤 사건으로 예약한다. 사망률, 임신률, 영아 생존, 혼인 전망은 econ_sim.py와 01번 8절 값을 썼다. 형질(장수, 강골, 병약, 다산, 불임 경향, 출혈병)이 사망과 임신을 바꾼다.
- 마을마다 부양 한계와 해마다 수확 변동이 있어 인구가 35.5만 명 근처에서 안정된다. 출생률, 사망률 연 3.1%, 평균 나이 25.8세.
- 같은 시드는 같은 검사합을 낸다.
- 요약 단계는 사실상 공짜다. 예산은 상세, 보통 단계가 쓴다. 그래서 죽은 사람을 세이브 파일로 내리는 일(5-6)은 당장 필요 없다. 161MB를 메모리에 둔다.
